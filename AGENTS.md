# AGENTS.md — job-parser-bot

- Режим проекта: рабочий (код пишет ИИ, Ивана не обучать).
- План фриланс-раздела и статусы: ai-knowledge `knowledge/job-parser-freelance-plan.md`; навыки `job-bot-fix`, `agentq-teamlead`.

## Роли и зоны

- Claude Code: тимлид, интеграция, весь Python-код (бот, парсеры, freelance/, tools/) и тесты.
- Codex: независимое ревью изменений по маршруту /agentq (read-only). Клиентского кода в проекте нет.
- Один автор на задачу; субагенты — только при явной необходимости.

## Защищённые зоны

- Базовые ограничения — ~/.claude/scripts/agentsrules.py, не ослаблять.
- `.env`, ключи, токены не читать, не выводить и не коммитить. `vacancies.db*` — локальные данные, не коммитить.
- Миграции БД — только аддитивные; проверка `python -m tools.migration_check` на синтетике обязательна.

## Проверки

- Тесты: `PYTHONUTF8=1 .venv/Scripts/python.exe -m unittest discover -s tests` (~15 мин, запускать в фоне).
- Миграция: `PYTHONUTF8=1 .venv/Scripts/python.exe -m tools.migration_check` (без `--db` — синтетика, боевую БД не трогает).
- `.agents/agentq.json` с `checks` нет: приёмка через `CR waive` с фактом прогона (SHA, число тестов).

## Публикация

- Push в main и слияние рабочих веток — сразу после проверок (тесты, секреты, конфликты).
- Только с «да» Ивана: деплой на BotHost, миграция прод-БД, включение отсекающего триажа, удаление данных.
- Force-push, `reset`, переписывание истории — только по прямой просьбе Ивана.
- Заказчикам автоматически ничего не отправлять; сообщения бота — только в `MY_CHAT_ID`.
